# ADR-0002：金额、汇率与舍入语义

| 字段 | 值 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-07-23 |
| 对应规格 | [`GLO-SPEC-000`](../spec.md) |
| 对应计划 | [`GLO-PLAN-000`](../plan.md) |

## 背景

预算是硬约束，而跨市场报价包含商品价、运费、税费、关税和多种币种。若使用二进制浮点、过早舍入或把未知费用当作零，系统可能把实际超预算商品错误放行。

M0 需要一种完全离线、可追溯、可重复的金额语义。

## 决策

### 表示

1. JSON 中金额和汇率使用十进制字符串。
2. 运行时使用 `decimal.Decimal`。
3. 拒绝 float、NaN、Infinity、负金额和非正汇率。
4. 已知零必须显式表示为 `"0.00"` 并带证据。
5. 未知费用使用 `UnknownCost(reason)`，不能用 `0` 或缺省值替代。

### 汇率

1. 每个快照声明一个 `base_currency`。
2. 每种币种声明正数 `base_per_unit` 和 0–4 的 `minor_units`。
3. 转换公式固定为：

```text
display_amount =
    source_amount
    × source_base_per_unit
    ÷ display_base_per_unit
```

4. 不访问实时汇率，不搜索汇率图，不自动补全缺失币种。
5. 汇率记录必须有 snapshot version 和 evidence。

### 计算与比较

1. 使用局部 Decimal context：precision 28、`ROUND_HALF_EVEN`。
2. 商品价、运费、税费和关税分别转换。
3. 计算过程中保留精确 Decimal，求和后才生成展示值。
4. 查询声明预算币种时，把未量化精确总额转换到该币种后比较；未声明时继承展示币种。
5. 预算币种或展示币种不在当前快照时，运行 `FAILED`，不能猜测汇率。
6. 展示值按目标币种 minor unit 量化。
7. 精确 JSON 使用 fixed-point、禁止指数并去除无意义尾随零；展示 JSON 严格保留 minor unit 位数。
8. selected offer 使用稳定键：

```text
(exact_landed_cost, provider_id, offer_id)
```

### 可追溯性

Landed Cost 必须保留：

- 原币费用分量；
- 每个分量的 evidence；
- source/display `base_per_unit`；
- 汇率快照版本；
- `pricing-v1` 算法版本；
- 精确总额和展示总额。

## 结果

正面影响：

- 预算边界不会受到浮点误差或展示舍入影响；
- 未知费用不会伪装成便宜报价；
- 每个输出金额都可从原始证据重算；
- 相同快照和配置产生相同金额。

代价：

- JSON 读写需要显式处理 Decimal 字符串；
- 输出同时包含精确值和展示值；
- M0 无法比较缺失必需费用的报价。

## 被否决的方案

### 使用 float

否决原因：不能稳定表达十进制金额，预算边界存在错误放行风险。

### 每个费用分量先量化再求和

否决原因：多次舍入会累积误差，且不同实现可能产生不同结果。

### 未知费用按零处理

否决原因：违反证据优先和硬预算原则。

### 运行时查询实时汇率

否决原因：破坏离线验收、可复现性和快照一致性。

## 后续复审条件

- 引入真实税费/关税服务；
- 支持退款、负向调整或优惠券；
- 支持需要不同 minor unit 或现金舍入规则的币种；
- 财务审计要求改变精度或舍入标准。

任何复审都必须保留“预算用精确值比较”和“未知不等于零”两个不变量。
